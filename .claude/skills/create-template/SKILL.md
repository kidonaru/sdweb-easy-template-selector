# create-template

入力プロンプトを Easy Template Selector のテンプレート形式（pnginfo 互換 .txt）へ変換するスキル。
テンプレートの各行はカテゴリコメント + タグ行のペアで構成され、コメントは JS パーサ
（`ets_prompt_editor.js` / `ets_section.js`）が解釈するため、形式を厳密に守る必要がある。

## テンプレート形式（厳守）

```
# URL: <出典URL>,            ← 出典があれば先頭に（任意）

# <カテゴリ>:<グループ> (<日本語ラベル>),
tag1, tag2,
# <カテゴリ> (<日本語ラベル>),
tag,
...
Negative prompt: # 99_ネガティブ:<グループ> (<ラベル>),
<ネガティブタグ列>,
Steps: 25, Sampler: DPM++ 2M, ... （メタデータ行）
```

### 各要素の対応

- `<カテゴリ>`: `tags/` の YAML ファイル名から拡張子を除いたもの（例: `23_表情`、`10_キャラ_ブルアカ`）。
- `<グループ>`: YAML 内のトップレベルキー（例: `基本`、`絵文字`）。グループが無いフラットな YAML では `:<グループ>` を省略。
- `(<日本語ラベル>)`: YAML 内でそのタグに付けたキー（日本語ラベル）。
- コメント行・タグ行はどちらも必ず `,` で終える。
- `Negative prompt:` 行以降がネガティブ、`Steps:` で始まる行以降がメタデータとして解釈される。

### セクションの並び順

- 入力プロンプトでのタグ出現順を優先する。カテゴリ番号による強制的な並び替えは行わない。
- 体型・見た目タグを固定のマリー欄（後述）に置き換える場合は、置き換えた元タグがあった位置に挿入する。
- 既存エントリが複数タグを 1 行にまとめていても（例: `1girl,1boy`）、それは「まとめて書ける」という意味に過ぎない。
- 入力プロンプト側でそれらのタグが離れた位置に出現している場合は分割する:
  - 各タグを元の出現位置のまま別セクションへ配置する
  - 例: `1girl` は前方の `# 02_対象 (一人の女の子)`、`1boy` は後方の `# 02_対象 (一人の男の子)`

### メタデータ行

- 同系統の既存テンプレート（templates/ 内）からコピーして流用する。
- Seed は `-1` にするか既存値のままで良い。

## 手順

### 1. 入力の解釈

入力プロンプトをタグ（またはシーン要素）に分解する。日本語説明の場合は Danbooru 系タグへ変換する。

### 2. 体型・見た目タグの置換

人物の外見を規定するタグ（体型・体格、髪型・髪色、目の色、キャラクター名、キャラ固有の衣装・装飾など）は**すべて削除**し、代わりに下記の固定セクションをテンプレートに含める:

```
# 11_体型 (若々しい/小柄),
youthful,petite,
# 10_キャラ_ブルアカ:トリニティ (マリー),
mari \(blue archive\),blue eyes,orange hair,mari halo,habit,single braid,hat flower,
# 13_衣装_ブルアカ:トリニティ (マリー),
nun,blue neckerchief,white sailor collar,white dress,armlet,mary janes,
```

- ポーズ・表情・背景・構図・シチュエーションなど外見以外のタグはそのまま残す。
- 入力の衣装タグがシーンの本質（例: 水着シーン等の状況指定）である場合は、無断で置き換えず `AskUserQuestion` で「マリー衣装に置き換える」か「入力の衣装タグを採用する（衣装のみ入力を残し、体型・キャラは固定セクションを使う）」かを確認する。それ以外のキャラ固有衣装は確認不要で上記マリー衣装に置き換える。

### 3. 既存タグの照合

各タグを `python tools/search_tags.py <検索語...>` で検索し、既存エントリがあればそのファイル名・グループ・日本語ラベルをコメントに使う（出力がそのままカテゴリコメント行の形式）。

- `tags/` は `.gitignore` 対象のため Grep ツールでは検索できない。必ず `search_tags.py` を使う。
- 表記ゆれ（スペース/アンダースコア）が疑われる場合は既定の部分一致のまま探す。"arch" のような短い語で無関係な結果が大量に出る場合は `--exact` を付けて絞り込む。
- 複数タグ結合済みのエントリがヒットし、対象タグが入力プロンプト内で隣接していない場合は結合を採用せず、単体タグとして個別に検索し直す（分割配置のルールは「セクションの並び順」参照）。
- `search_tags.py` は `tags/*.yml` 内の既存表記と照合するだけで、その表記が Danbooru 上で有効なタグかどうかは保証しない。単数/複数形や語形が怪しいもの（例: `sound effect`）は、既存エントリを流用する場合でも「Danbooru 実在確認」（後述）を行う。

**複合シーン記述の扱い**: 入力の 1 セグメントが構図・関係性・状況を表す一塊のフレーズの場合（例: `faceless man behind sit sofa`）、単語ごとに既存タグへ分解しない。

- 各単語が個別に既存タグへ部分一致しても、分解してよい根拠にはならない。
- フレーズ全体が指す意味単位を優先する。
- 最も適切なカテゴリの `オリジナル` 系グループへ、入力表記のまま（翻訳・タグ変換せず）1 つの新規エントリとして追記する。

### 4. 不足タグの追加

検索で見つからないタグは、「Danbooru 実在確認」（後述）を行った上で、意味的に最も近いカテゴリの YAML の適切なグループへ、日本語ラベル付きで追記する。

追記時のルール:

- タグ文字列は入力の表記をそのまま使う。完全一致しないからといって、強度修飾語（"slightly" 等）を無断で省略したり、似た既存タグに丸めたりしない。省略・統合したい場合は追記前に必ずユーザーに確認する。
- ファイル命名規則 `番号_カテゴリ名[_サブ分類].yml` と番号帯（01=クオリティ、10番台=キャラ/衣装、20番台=表情、30番台=ポーズ、40番台=アングル、50番台=背景、60番台以降=効果/その他、99=ネガティブ）を守る。
- 既存ファイルに収まらない場合のみ新規 YAML を作る（番号帯を合わせる）。
- 追記後は `python -c "import yaml, sys; yaml.safe_load(open(sys.argv[1], encoding='utf-8'))" tags/対象.yml` で構文確認する。

### 5. テンプレート組み立て

- 「テンプレート形式」に従いセクションを並べる。
- クオリティ・レーティング・ネガティブ・メタデータは同系統の既存テンプレートから流用する（入力に指定があればそちらを優先）。
- 入力にネガティブプロンプトの指定が無い場合は、`# 99_ネガティブ:Model (Nova Anime XL)` をデフォルトとして使う。

### 6. 保存

内容が SFW なら `templates/01_SFW/`、NSFW なら `templates/02_NSFW/` に、内容を表す日本語ファイル名（例: `夕暮れの屋上 制服.txt`）で UTF-8 保存する。

### 7. 報告

以下を一覧で報告する:

- 作成したテンプレートのパス
- 流用したタグ
- 追加したタグ（追記先 YAML とラベル）
- 実在未確認・未検証のタグがあればその旨（「Danbooru 実在確認」参照）

## Danbooru 実在確認

新規追記するタグ、および既存エントリでも語形が怪しいタグは、追記・流用の前に `python tools/search_danbooru.py <タグ> --exact` で実在確認する（例: `python tools/search_danbooru.py "sound effects" --exact`）。

結果の読み方:

| 結果 | 意味 | 対応 |
|---|---|---|
| `OK` | 実在する | そのまま使用 |
| `OK(alias)` | 別名経由で実在 | 別名解決先の正式タグ名を使う（下記例参照） |
| `NG` | 実在しない | 下記「NG だった場合」へ |

`OK(alias)` の例: `hair ornaments`→`hair ornament`、`hair braid`→`braid`（入力表記のエイリアスのままでは追記しない）。

単数/複数形の思い込み（`sound effect` ではなく `sound effects`、`pastel color` ではなく `pastel colors` 等）や語順違いで、存在しないタグを作らないよう注意する。

### NG だった場合

1. `--exact` を外した部分一致検索で正式な表記が無いか確認する。この部分一致検索は、複合シーン記述（手順 3 参照）以外の全ての NG タグで省略しない。
2. 意味の近い実在タグ・エイリアスが見つかった場合: 無断で置換せず、また無断でそのまま追記もせず、`AskUserQuestion` で「実在タグへの置換」か「入力表記のまま追記」かを確認してから確定する。
3. それでも相当タグが一切見つからない場合: 入力プロンプト由来の独自表現としてそのまま追記してよいが、実在しない旨をユーザーへの報告に含める。

### 例外

- **`on <名詞>` 形式**（例: `on tatami`）: 名詞部分（`tatami` 等）が実在すれば `on` 付きの表記のまま許容する。ユーザーへの確認は不要。
- **括弧を含むタグ**（例: `kim possible (series)`）: 完全一致で NG になっても括弧部分を削除しない。括弧は `\(` `\)` でエスケープして保持し（`mari \(blue archive\)` と同じ慣習）、Danbooru 上で未検証である旨を報告に含めるだけに留める。
- **ツールが使えない場合**: 「Danbooru タグ CSV が見つかりません」エラーで失敗する場合（`a1111-sd-webui-tagcomplete` 拡張が未導入等）は、実在確認自体をスキップし、その旨をユーザーへの報告に含めた上で先に進んでよい。

## 例

入力: `1girl, sitting on bench, autumn leaves, scarf, gentle smile`

- `1girl` → `02_対象` に既存（一人の女の子）→ 流用
- `scarf` → 見た目（衣装）タグのため**削除**し、固定のマリー体型/キャラ/衣装セクションを挿入
- `sitting on bench` → `30_ポーズ` を検索、無ければ `30_ポーズ.yml` の適切なグループに `ベンチに座る: sitting on bench` を追記
- `autumn leaves` → `50_背景` 系に無ければ追記（例: `紅葉: autumn leaves`）
- `gentle smile` → `23_表情` の `基本` グループへ追記

出力（抜粋、入力の出現順: 1girl → sitting on bench → autumn leaves → scarf → gentle smile を維持）:

```
# 01_クオリティ:Model (Nova Anime XL),
masterpiece, best quality, ...,
# 02_対象 (一人の女の子),
1girl,solo,
# 30_ポーズ:基本 (ベンチに座る),
sitting on bench,
# 50_背景:自然 (紅葉),
autumn leaves,
# 10_キャラ_ブルアカ:トリニティ (マリー),
mari \(blue archive\),blue eyes,orange hair,mari halo,habit,single braid,hat flower,
# 11_体型 (若々しい/小柄),
youthful,petite,
# 13_衣装_ブルアカ:トリニティ (マリー),
nun,blue neckerchief,white sailor collar,white dress,armlet,mary janes,
# 23_表情:基本 (優しい微笑み),
gentle smile,
Negative prompt: # 99_ネガティブ:Model (Nova Anime XL),
...（既存テンプレから流用）
Steps: 25, Sampler: DPM++ 2M, ...（既存テンプレから流用）
```

## 注意

- コメント行の形式が崩れると UI 上でセクション分解できなくなる。必ず `# カテゴリ[:グループ] (ラベル),` 形式にする。
- 既存 YAML の既存エントリは変更しない（追記のみ）。
- タグの重複追加をしない: 追記前に必ず `tools/search_tags.py` で該当タグを検索する。
- LoRA タグ（`<lora:...>`）は対象の性質に応じたカテゴリの `_LoRA` サブファイルを使う: キャラ LoRA は 10 番台（`10_キャラ_LoRA.yml` 等）、衣装 LoRA は 13 番台（`13_衣装_LoRA.yml`）、ポーズ LoRA は 30 番台（`30_ポーズ_LoRA.yml`）、スタイル/ディテール等の汎用 LoRA のみ 70 番台。該当する `_LoRA` サブファイルが無ければ番号帯を合わせて新規作成する。入力に無ければ追加しない。
