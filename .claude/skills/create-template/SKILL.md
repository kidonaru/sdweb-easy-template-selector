# create-template

入力プロンプトを Easy Template Selector のテンプレート形式（pnginfo 互換 .txt）へ変換するスキル。
テンプレートの各行はカテゴリコメント + タグ行のペアで構成され、コメントは JS パーサ
（`ets_prompt_editor.js` / `ets_section.js`）が解釈するため、形式を厳密に守る必要がある。

## テンプレート形式（厳守）

```
# URL: <出典URL>,            ← 出典があれば先頭に（任意）

# <カテゴリ>:<グループ> (<日本語ラベル>),
tag1, tag2,
# <カテゴリ> (<日本語ラベル>),
tag,
...
Negative prompt: # 99_ネガティブ:<グループ> (<ラベル>),
<ネガティブタグ列>,
Steps: 25, Sampler: DPM++ 2M, ... （メタデータ行）
```

ルール:
- `<カテゴリ>` は `tags/` の YAML ファイル名から拡張子を除いたもの（例: `23_表情`、`10_キャラ_ブルアカ`）。
- `<グループ>` は YAML 内のトップレベルキー（例: `基本`、`絵文字`）。グループが無いフラットな YAML では `:<グループ>` を省略。
- `(<日本語ラベル>)` は YAML 内でそのタグに付けたキー（日本語ラベル）。コメント行は必ず `,` で終える。
- タグ行も `,` で終える。
- セクションの並びは入力プロンプトでのタグ出現順を優先する（カテゴリ番号による強制的な並び替えは行わない）。体型・見た目タグを固定のマリー欄（10_キャラ/11_体型/13_衣装）に置き換える場合は、置き換えた元タグがあった位置に挿入する。
- `search_tags.py` が複数タグを1行にまとめた既存エントリ（例: `1girl,1boy`）を返しても、それは「まとめて書ける」という意味に過ぎない。入力プロンプト側でそれらのタグが離れた位置に出現している場合は、まとめて1セクションにせず、各タグを元の出現位置のまま別セクションに分割する（例: `1girl` は前方の `# 02_対象 (一人の女の子)`、`1boy` は後方の `# 02_対象 (一人の男の子)`）。
- `Negative prompt:` 行以降がネガティブ、`Steps:` で始まる行以降がメタデータとして解釈される。
- メタデータ行は既存テンプレート（同系統の templates/ 内ファイル）からコピーして流用する。Seed は `-1` にするか既存値のままで良い。

## 手順

1. **入力の解釈**: 入力プロンプトをタグ（またはシーン要素）に分解する。日本語説明の場合は Danbooru 系タグへ変換する。
2. **体型・見た目タグの置換**: 入力プロンプト中の体型・見た目に関するタグ（体型・体格、髪型・髪色、目の色、キャラクター名、キャラ固有の衣装・装飾など、人物の外見を規定するもの）は**すべて削除**し、代わりに下記の固定セクションをテンプレートに含める:

   ```
   # 11_体型 (若々しい/小柄),
   youthful,petite,
   # 10_キャラ_ブルアカ:トリニティ (マリー),
   mari \(blue archive\),blue eyes,orange hair,mari halo,habit,single braid,hat flower,
   # 13_衣装_ブルアカ:トリニティ (マリー),
   nun,blue neckerchief,white sailor collar,white dress,armlet,mary janes,
   ```

   ポーズ・表情・背景・構図・シチュエーションなど外見以外のタグはそのまま残す。入力の衣装タグがシーンの本質（例: 水着シーン等の状況指定）である場合も、キャラ固有衣装は上記マリー衣装で置き換える。
3. **既存タグの照合**: 各タグについて `python tools/search_tags.py <検索語...>` で検索し、既存エントリがあればそのファイル名・グループ・日本語ラベルをコメントに使う（出力がそのままカテゴリコメント行の形式）。`tags/` は `.gitignore` 対象のため Grep ツールでは検索できない。表記ゆれ（スペース/アンダースコア）が疑われる場合は既定の部分一致のまま探し、"arch" のような短い語で無関係な結果が大量に出る場合は `--exact` を付けて絞り込む。検索結果が複数タグ結合済みのエントリ（例: `1girl,1boy`）だった場合でも、対象タグが入力プロンプト内で隣接していないなら結合を採用せず、単体タグとして個別に検索し直して元の出現位置に配置する。
   - `search_tags.py` は `tags/*.yml` 内の既存表記と照合するだけで、その表記が実際に Danbooru 上で有効なタグかどうかは保証しない。既存エントリを流用する場合でも、単数/複数形や語形が怪しい場合（例: `sound effect`）は次項と同様に `tools/search_danbooru.py` で実在確認する。
4. **不足タグの追加**: 見つからないタグは、意味的に最も近いカテゴリの YAML の適切なグループへ、日本語ラベル付きで追記する。
   - 追記前に `python tools/search_danbooru.py <タグ> --exact` で Danbooru 実在確認する（例: `python tools/search_danbooru.py "sound effects" --exact`）。`OK` なら実在、`OK(alias)` なら別名経由で実在、`NG` なら実在しない。単数/複数形の思い込み（`sound effect` ではなく `sound effects`、`pastel color` ではなく `pastel colors` 等）や語順違いで存在しないタグを作らないよう注意する。`NG` の場合は正式な表記が無いか `--exact` を外した部分一致検索で確認する。それでも Danbooru に相当タグが無い場合は、それが入力プロンプト由来の独自表現であることを踏まえた上でそのまま追記してよいが、実在しない旨をユーザーへの報告に含める。ただし `on tatami` のような `on <名詞>` 形式は、名詞部分（`tatami` 等）が実在すれば `on` 付きの表記のまま許容し、ユーザーへの確認は不要とする。ツールが「Danbooru タグ CSV が見つかりません」エラーで失敗する場合（`a1111-sd-webui-tagcomplete` 拡張が未導入等）は、この確認手順自体をスキップし、その旨をユーザーへの報告に含めた上で先に進んでよい。
   - 追記するタグ文字列は入力の表記をそのまま使う。検索で完全一致しないからといって、強度修飾語（"slightly" 等）を無断で省略したり、似た既存タグに丸めたりしない。省略・統合したい場合は追記前に必ずユーザーに確認する。
   - ファイル命名規則 `番号_カテゴリ名[_サブ分類].yml` と番号帯（01=クオリティ、10番台=キャラ/衣装、20番台=表情、30番台=ポーズ、40番台=アングル、50番台=背景、60番台以降=効果/その他、99=ネガティブ）を守る。
   - 既存ファイルに収まらない場合のみ新規 YAML を作る（番号帯を合わせる）。
   - 追記後は `python -c "import yaml, sys; yaml.safe_load(open(sys.argv[1], encoding='utf-8'))" tags/対象.yml` で構文確認する。
5. **テンプレート組み立て**: 上記形式でセクションを並べ、クオリティ・レーティング・ネガティブ・メタデータは同系統の既存テンプレートから流用する（入力に指定があればそちらを優先）。入力にネガティブプロンプトの指定が無い場合は、`# 99_ネガティブ:Model (Nova Anime XL)` をデフォルトとして使う。
6. **保存**: 内容が SFW なら `templates/01_SFW/`、NSFW なら `templates/02_NSFW/` に、内容を表す日本語ファイル名（例: `夕暮れの屋上 制服.txt`）で UTF-8 保存する。
7. **報告**: 作成したテンプレートのパス、流用したタグ、追加したタグ（追記先 YAML とラベル）を一覧で報告する。

## 例

入力: `1girl, sitting on bench, autumn leaves, scarf, gentle smile`

- `1girl` → `02_対象` に既存（一人の女の子）→ 流用
- `scarf` → 見た目（衣装）タグのため**削除**し、固定のマリー体型/キャラ/衣装セクションを挿入
- `sitting on bench` → `30_ポーズ` を検索、無ければ `30_ポーズ.yml` の適切なグループに `ベンチに座る: sitting on bench` を追記
- `autumn leaves` → `50_背景` 系に無ければ追記（例: `紅葉: autumn leaves`）
- `gentle smile` → `23_表情` の `基本` グループへ追記

出力（抜粋、入力の出現順: 1girl → sitting on bench → autumn leaves → scarf → gentle smile を維持）:

```
# 01_クオリティ:Model (Nova Anime XL),
masterpiece, best quality, ...,
# 02_対象 (一人の女の子),
1girl,solo,
# 30_ポーズ:基本 (ベンチに座る),
sitting on bench,
# 50_背景:自然 (紅葉),
autumn leaves,
# 10_キャラ_ブルアカ:トリニティ (マリー),
mari \(blue archive\),blue eyes,orange hair,mari halo,habit,single braid,hat flower,
# 11_体型 (若々しい/小柄),
youthful,petite,
# 13_衣装_ブルアカ:トリニティ (マリー),
nun,blue neckerchief,white sailor collar,white dress,armlet,mary janes,
# 23_表情:基本 (優しい微笑み),
gentle smile,
Negative prompt: # 99_ネガティブ:Model (Nova Anime XL),
...（既存テンプレから流用）
Steps: 25, Sampler: DPM++ 2M, ...（既存テンプレから流用）
```

## 注意

- コメント行の形式が崩れると UI 上でセクション分解できなくなる。必ず `# カテゴリ[:グループ] (ラベル),` 形式にする。
- 既存 YAML の既存エントリは変更しない（追記のみ）。
- タグの重複追加をしない: 追記前に必ず `tools/search_tags.py` で該当タグを検索する。
- LoRA タグ（`<lora:...>`）は 70 番台のカテゴリを使う。入力に無ければ追加しない。
