# tags/*.yml 一括 Danbooru 実在検証 設計

日付: 2026-07-23

## 目的

`tools/search_danbooru.py` にタグを1件ずつ手動で確認するモード（`--exact`）はあるが、`tags/*.yml` 内の全タグをまとめて検証する手段がない。YAML ファイル（または `tags/` ディレクトリ）を指定するだけで、含まれる全タグの Danbooru 実在確認を一括で走らせ、実在しないタグ（誤字・単複違い等）をレポートできるようにする。

## 仕様

### CLI

既存の `tools/search_danbooru.py` に `--yaml` モードを追加する（別スクリプトにはしない）。

```
python tools/search_danbooru.py --yaml <PATH> [<PATH> ...] [--exclude-category PREFIX ...]
```

- `<PATH>` はファイル（`tags/xx.yml`）またはディレクトリ（`tags/` 等）を混在指定可能。ディレクトリの場合は直下の `*.yml` を非再帰でグロブする（`tools/search_tags.py` の `load_entries` と同じ挙動）。
- `--exclude-category` は `tools/search_tags.py` と同じ「ファイル名プレフィックス」方式（例: `--exclude-category 01_クオリティ` は `01_クオリティ.yml` を除外）。
- `--yaml` 指定時は位置引数 `queries` を使わない。`--yaml` と `queries` の同時指定はエラーとする。
- `--exact` は `--yaml` モードでは無視してよい概念（`--yaml` は常に完全一致検証のため）。`--limit` も `--yaml` モードでは意味を持たない。両者を同時指定してもエラーにはしない（単に無視される）。

### データフロー

1. `--yaml` の各パスを解決し、対象 `*.yml` ファイル一覧を確定する。
2. 各ファイルを `yaml.safe_load` し、`tools/search_tags.py` の `flatten()` を import して `(filename, group, label, tags文字列)` に平坦化する（パースロジックの重複を避ける）。YAML構文エラーや非辞書ファイルは `search_tags.py` の `load_entries` と同様、警告を出してスキップし処理を継続する。
3. `--exclude-category` でファイル名プレフィックス一致分を除外する。
4. `tags文字列` に `<lora:` が含まれるエントリは丸ごと検証対象から除外する（後述）。
5. 残ったエントリの `tags文字列` をタグ単位に分解する（後述）。
6. 各タグを `query_exact()` で検証し、`ensure_db()` で通常モードと同じキャッシュ DB を利用する。

### LoRA エントリの扱い

`tags文字列` に `<lora:` という部分文字列が含まれるエントリは、そのエントリ全体を検証対象から除外する（`purple eyes` のような実タグが同じエントリ内に混在していても検証しない）。

理由: LoRA 系エントリ（例: `<lora:HinaBlueArchiveIXL:1.0> zzHina, purple eyes, ...`）にはトリガーワード（`zzHina` 等、Danbooru に存在しない文字列）が含まれ、これを本文タグと機械的に区別するのは信頼性が低い。同等のタグは非LoRA版の姉妹ファイル（例: `10_キャラ_ブルアカ.yml` に対する `10_キャラ_ブルアカ_LoRA.yml`）で既に検証されるため、エントリ単位スキップによる取りこぼしは限定的。

### タグ抽出（LoRAエントリを除いた各エントリの `tags文字列` → 個別タグへの分解）

1. カンマで分割する。
2. 各トークンの前後空白を除去する。
3. トークン全体が `(<内容>:<数値>)` の重みラップ形式であれば、外側の `(` `)` と `:<数値>` を剥がして `<内容>` だけを残す（例: `(ibuki \(blue archive\):0.7)` → `ibuki \(blue archive\)`）。内側のエスケープ `\(` `\)` はタグ名の一部としてそのまま残す。
4. 空トークンは無視する。

このプロジェクトの実データにカンマを含む重みグループ（例: `(tag1, tag2:1.1)`）が存在しないことを確認済みのため、単純なカンマ分割で問題ない。

### 検証

分解した各タグ文字列を `query_exact(conn, tag)` にかける。部分一致（`query_partial`）は使わない（実在確認が目的のため）。

### 出力形式

NG（未検出）のみを一覧表示し、ファイル別・全体のサマリを末尾に出す。OK・alias経由OKは表示しない（ノイズ削減のため）。

```
NG 10_キャラ_ブルアカ:トリニティ (マリー) tag='mari halo': Danbooru に実在するタグは見つかりませんでした（別名含め未検出）。
NG 10_キャラ_ブルアカ:ゲヘナ (ヒナ) tag='hina halo': Danbooru に実在するタグは見つかりませんでした（別名含め未検出）。
...
--- サマリ ---
10_キャラ_ブルアカ.yml: 2/48件 NG
10_キャラ_ブルアカ_LoRA.yml: 0/0件 NG（LoRAエントリのため42件スキップ）
合計: 2/48件 NG（LoRAスキップ合計42件）
```

- 1タグにつき1行で `NG <ファイル名>[:<グループ>] (<ラベル>) tag='<タグ>': <query_exact結果のNGメッセージ>` の形式（カテゴリ表記部分は `search_tags.py` の `format_comment()` が返す `# カテゴリ[:グループ] (ラベル),` から先頭 `#` と末尾 `,` を取り除いたものと同一の組み立て方にする）。
- ファイル別サマリは `<ファイル名>.yml: NG件数/検証対象タグ総数件 NG`。スキップ件数があれば括弧書きで併記。
- 全体サマリは `合計: NG件数/検証対象タグ総数件 NG（LoRAスキップ合計N件）`。
- 終了コードは常に 0（レポート専用ツールであり、CI 的なゲート用途は想定しない）。

### エラーハンドリング

- `--yaml` に存在しないパスを渡した場合はそのパスについて警告を出しスキップする（他のパスの処理は継続）。
- Danbooru タグ CSV が見つからない場合は既存の `--exact` モードと同じくエラー終了する（`ensure_db` の挙動は変えない）。

## 変更対象

| ファイル | 変更内容 |
|---|---|
| `tools/search_danbooru.py` | `--yaml` / `--exclude-category` 引数を追加。YAML パス解決・`search_tags.flatten()` 呼び出し・LoRAエントリスキップ・タグ抽出（カンマ分割+重み剥がし）・NGレポート出力・サマリ集計の関数群を追加。`main()` に `--yaml` 指定時の分岐を追加 |
| `tools/search_tags.py` | 変更なし（`flatten()` を import して再利用するのみ） |

## 影響範囲

- 既存の `--exact` / 部分一致モード（`queries` 位置引数を使う通常フロー）は無変更。
- `tools/search_tags.py` は import 元として参照されるのみで、ロジック変更なし。
- `.claude/skills/create-template/SKILL.md` は本設計の対象外（既存タグ追記の都度確認フローは変更しない。将来的に一括検証をスキル手順に組み込むかは別途判断）。

## テスト方針

ビルド・テスト基盤はないため、`docs/superpowers/plans/2026-07-22-tag-search-script.md` および `2026-07-23-danbooru-tag-verify-tool.md` の先例に倣い、フィクスチャYAML + フィクスチャCSVに対する assert ベースの検証スクリプトと、実データ（`tags/` 配下の実ファイル）に対する手動実行で確認する。

1. フィクスチャ: LoRAエントリ・重みラップ・カンマ区切り複数タグ・存在しないタグを含む小さなYAMLを用意し、`--yaml` 実行結果（NG一覧・サマリの件数）を assert する。
2. 実データ: `tags/10_キャラ_ブルアカ.yml` 単体指定、`tags/` ディレクトリ一括指定、`--exclude-category` 指定の3パターンを実行し、出力が妥当か目視確認する。
