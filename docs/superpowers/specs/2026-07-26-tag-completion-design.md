# プロンプト補完機能 設計

## 目的

txt2img のプロンプト欄で `#` に続けて入力すると、`tags/*.yml` のエントリを日本語ラベル・英語タグ・カテゴリ名で検索し、ETS のセクション形式（`# カテゴリ (ラベル),` ＋ タグ行）へ展開する。

## 背景

同環境には `a1111-sd-webui-tagcomplete` が導入済みだが、あれはカンマ区切りのインライン補完であり、ETS の「1 セクション = コメント行＋タグ行の 2 行」というフォーマットと噛み合わない。また Danbooru の英語タグしか引けないため、日本語ラベルで管理している `tags/*.yml` の資産を活かせない。

トリガを行頭の `#` に限定することで tagcomplete と衝突させず、両方を使い分けられる状態にする。

## スコープ外

- img2img（ETS 自体が txt2img 専用）
- `00_テンプレート` / `90_モデル` / `96_解像度` の補完。いずれもテキスト挿入以外の副作用（テンプレ全体の適用・モデル切替・Width/Height 変更）を持ち、「行を展開する」という単一の振る舞いに収まらない。ETS パネルからの選択で従来どおり操作する
- tagcomplete の置き換え・無効化

## ファイル構成

| ファイル | 責務 |
|---|---|
| `javascript/ets_completion_index.js`（新規） | `ETSCompletionIndex`: タグツリーの平坦化と `search(query, target)` |
| `javascript/ets_completion.js`（新規） | `ETSCompletion`: textarea へのキー配線、ポップアップ制御、確定処理 |
| `javascript/ets_element_builder.js`（追記） | ポップアップの DOM 生成 |
| `javascript/easy_template_selector.js`（追記） | `init()` 内での結線とインデックス構築 |
| `style.css`（追記） | ポップアップのスタイル |

`ETSCompletion` には `ETSCompletionIndex` と `ETSHistory`（Undo 履歴の保存に使う）を注入する。`ETSPromptEditor` には依存しない。

既存規約に従い、DOM 生成は `ETSElementBuilder` に集約する。各ファイルはトップレベルで他クラスを参照せず、参照は `onUiLoaded` 以降の実行時に限る。

## 補完インデックス

`easy_template_selector.js` の `renderTagButtons()` と同じ再帰でタグツリーを歩き、1 エントリを `{ comment, tag, category }` に平坦化する。この 3 つ組は `ETSSection` のコンストラクタ引数とそのまま一致する。

- ランダムエントリ（`@カテゴリ@` / `@カテゴリ:グループ@`）も候補に含める。ETS パネルのボタンと同じ単位にする
- 除外カテゴリ（`00_テンプレート` / `90_モデル` / `96_解像度`）は平坦化の時点で落とす
- 除外グループ（`01_クオリティ:Model` / `99_ネガティブ:Model`）も落とす。`ETSPromptEditor.applyModelTag()` がこの 2 グループのセクションを `replaceSection()` で差し替えるが先頭 1 件しか置換しないため、補完でセクションが重複するとモデル切替が壊れる
- ETS の Reload 時にインデックスを再構築する

### 検索仕様

`search(query, target)` の `target` は `positive` / `negative` のいずれか。

1. **入力欄によるフィルタ**（先に適用）
   - `positive`: `category` が `99_ネガティブ` で始まるエントリを除外
   - `negative`: `category` が `99_ネガティブ` で始まるエントリのみ
2. **マッチ**: `comment`（日本語ラベル）/ `tag`（英語）/ `category`（`20_目の状態`, `10_キャラ_ブルアカ:トリニティ`）への部分一致。大文字小文字を区別しない
3. **優先順**: ラベル前方一致 → ラベル部分一致 → タグ一致 → カテゴリ一致。同順位内はカテゴリ番号順
4. **上限**: 20 件

### 表示形式

`20_目の状態 (細めた目)` を主表示、右側に薄く `narrowed eyes` を添える。

## トリガとポップアップ

- **対象**: `txt2img_prompt` / `txt2img_neg_prompt`
- **起動条件**: 以下をすべて満たすとき
  - カーソル行が `#` で始まる
  - カーソル行**全体**に `,` `(` `)` のいずれも含まれない。既存のコメント行（`# 20_目の状態 (細めた目),`）は必ずこれらを含むため、行の途中にカーソルを置いても発火しない
  - クエリ（`#` 直後からカーソルまでの文字列）が 1 文字以上
- **閉じる条件**: 上記の起動条件を満たさなくなった／候補が 0 件／Esc／blur
- **候補 0 件なら開かない** — 従来どおり普通のコメント行として書ける
- **キー操作**: ↑↓ で選択移動、Enter / Tab で確定、Esc で閉じる。確定時の Enter は改行を `preventDefault` する
- **IME**: `event.isComposing` が真の Enter は変換確定として素通しし、補完確定には使わない。日本語ラベル検索が主軸のため必須
- **表示位置**: textarea の直下に左寄せで固定。キャレット座標への追従はミラー要素での座標計算が必要で、Gradio のレイアウト変更に対して壊れやすいため採用しない。`position: fixed` でビューポート座標に置き、要素は gradio コンテナ配下に入れる（テーマの CSS 変数を解決させるため）。スクロール・リサイズには追従させず閉じる
- **キーイベントの配線先**: keydown は `gradioApp()` の捕捉フェーズで受ける。textarea 自身に登録すると `eventPhase` が `AT_TARGET` になり `capture: true` を付けても登録順でしか呼ばれないため、他拡張より先に処理できる保証がない

### tagcomplete との共存

行頭 `#` をトリガにすれば衝突しないことを、tagcomplete のソースで確認済み。

- 検索語はカンマ区切りで切り出されるため `#細めた` は `#` ごと 1 語になる。通常タグの検索正規表現 `(^|[^a-zA-Z])<語>` は danbooru の CSV に一致せず必ず 0 件になり `hideResults()` される
- `navigateInList()` は自分のポップアップが表示されているときしかキーを消費しない
- tagcomplete の `input` リスナは `inputType` の無いイベントを無視するため、`updateInput()` で誤発火しない

tagcomplete 側の設定でパーサや翻訳を増やした場合はこの前提が崩れうるので、共存を再確認する。

## 確定処理

`promptEditor.addTag()` は経由せず、カーソル行をその場で置き換える。

1. `new ETSSection(comment, tag, category).toString()` で挿入テキストを生成
2. カーソル行（`#...`）をその文字列で置換し、`updateInput()` を呼ぶ
3. キャレットを挿入テキストの末尾（タグ行の行末）へ移動
4. `history.saveTextHistory()` を呼び Undo 可能にする

### 帰結

- `97_Color` / `98_特殊` は `ETSSection.toString()` がタグのみを返す既存仕様がそのまま効き、コメント行なしの 1 行になる
- ネガティブ欄への振り分けは行わない。入力欄によるフィルタにより、そもそもポジ欄にネガティブ候補は出ない
- 同カテゴリの重複は解消しない。`# 20_目の状態` が既にあっても 2 つ目がその場に増える。カーソル位置に入れるという規則を優先し、`addTag()` の置換ロジックは持ち込まない
- `addTag()` 固有の追加モード（Ctrl+クリック相当）は概念として存在しないため、確定は Enter / Tab のみ
- ラベル検索は行に `(` が入った時点で止まるため、`マリー(体操服)` のようにカッコを含むラベルは `マリー` までしか打てない。前方部分で絞って候補から選ぶ
- 候補が出ている間の Enter は確定に使われる。普通に改行したいときは Esc で閉じてから
- `ETSHistory` は変更後の状態だけを積むため、セッション最初の操作が補完確定だと戻り先が無く Undo が効かない（既存の ETS ボタン経由の追加と同じ挙動）

## エラー処理

- タグ未読込・インデックスが空なら何もしない（ポップアップを開かない）
- 除外カテゴリしか一致しない場合は候補 0 件として扱う

## テスト方針

`ETSCompletionIndex` と `ETSCompletion.extractQuery()`（トリガ判定）は DOM 非依存の純粋ロジックなので、`node:test` による単体テストを `tests/` に添える（CLAUDE.md の「WebUI 非依存の純粋モジュールにはテストを添える」に従う）。外部依存は追加しない。

- `tests/ets_completion_index.test.mjs`: 平坦化・カテゴリ/グループ除外・ポジ/ネガフィルタ・優先順・件数上限
- `tests/ets_completion.test.mjs`: トリガ判定・クエリ抽出・行置換

実行はリポジトリルートで `node --test`。ファイル名を `*.test.mjs` にしているのは Node の既定検出パターンが `test_*.mjs` を拾わないため（`tests/` に同居する Python の `test_*.py` とも干渉しない）。

DOM 配線・ポップアップ・確定処理は WebUI 上での手動確認とする。確認項目:

1. 日本語ラベルで検索し確定 → 2 行に展開される
2. 英語タグで検索し確定
3. カテゴリ名・グループ名で検索
4. IME 変換中の Enter で補完が確定してしまわない
5. ポジ欄に `99_ネガティブ` の候補が出ない／ネガ欄に他カテゴリの候補が出ない
6. `97_Color` / `98_特殊` がコメント行なしの 1 行で入る
7. `00_テンプレート` / `90_モデル` / `96_解像度` が候補に出ない
8. 候補 0 件のときポップアップが出ず、普通のコメント行として書ける
9. 確定後に Undo で元に戻る
10. 既存のコメント行（`# 20_目の状態 (細めた目),`）にカーソルを置いても発火しない
11. tagcomplete のポップアップと同時に出ない
