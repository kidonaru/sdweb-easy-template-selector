# キャラ/衣装差し替え一括生成（バッチ生成）設計

作成日: 2026-08-02

## 目的

現在のプロンプト欄に組んだキャラ+衣装の指定を差し替え元として、選択した複数テンプレートのキャラ/衣装セクションを差し替えながら 1 件ずつ順次生成できるようにする。特定キャラでテンプレ群を横断的に一括生成するのが主用途。

## 決定事項（ヒアリング結果）

- 置換単位: キャラ+衣装（`10_キャラ*` + `13_衣装*` / `14_衣装小物*` / `15_衣装状態*` プレフィックス帯）
- 差し替え元: 現在のポジティブプロンプト欄から抽出（専用の選択 UI やプリセットファイルは作らない）
- 実行方式: JS オーケストレーション。既存の `applyTemplate()` フローを再利用し、UI 上で順次実行（案 A）
- 対象テンプレ: 既存テンプレ一覧にチェックボックスを出して個別選択
- キャラ指定のないテンプレ: 差し替えず**そのまま生成**（挿入もスキップもしない）
- Seed: テンプレに焼かれた値をそのまま使う（`applyTemplate` の既存動作に任せる）

## コンポーネント構成

### 1. `javascript/ets_batch_runner.js` — `ETSBatchRunner`（新規）

バッチ実行の中核。責務は 3 つ。

**キャラ/衣装セクションの抽出・差し替え**

- `ETSPromptEditor.parseSection` と同じヘッダー規約（`# カテゴリ:グループ (ラベル),` + タグ行、末尾 `)` アンカーの正規表現）でプロンプトをセクション列に分解する
- 対象プレフィックスは定数 `SWAP_PREFIXES = ['10_キャラ', '13_衣装', '14_衣装小物', '15_衣装状態']`。カテゴリ名の前方一致で判定（`10_キャラ_ブルアカ` 等のサブ分類も拾う）
- 差し替え位置: テンプレ側の**最初の対象セクションがあった位置**にキャラ+衣装一式をまとめて挿入し、残りの対象セクションは削除する
- テンプレに対象セクションが 1 つも無い場合は差し替えを行わない
- 抽出・差し替えロジックは DOM 非依存の純粋関数として切り出す（単体テスト対象）

**実行キュー制御**

- 選択テンプレを 1 件ずつ処理する async ループ
- 中断フラグを持ち、「停止」ボタンで現在の生成完了後に打ち切る
- 実行開始時にポジティブ欄から差し替え元セクションを抽出して固定する（実行中のプロンプト欄の変化に影響されない）

**待機処理**

- テンプレ適用後の安定待ち: `applyTemplate()` は pnginfo 貼り付け（Gradio 非同期ラウンドトリップでプロンプト欄を書き戻す）+ `setTimeout(1500)` のメタ反映 + 非同期モデル切替（`selectCheckpoint`）を含む。差し替えはこの書き戻しが済んだ後に行う必要があるため、「プロンプト欄がテンプレ内容と一致」かつ「モデル名が一致（モデル反映 ON 時のみ）」をポーリングし、さらにメタ反映猶予（2 秒程度）を置いてから差し替え → Generate する。適用待ちのタイムアウトは 5 分（モデルロードを含むため）
- 生成完了待ち: `#txt2img_generate` ボタンの表示状態（生成中は Interrupt/Skip 表示に切り替わる）を 500ms 間隔でポーリングし、通常状態への復帰を完了とみなす。タイムアウトは 15 分/件

### 2. テンプレ一覧のチェックボックス UI（`easy_template_selector.js` + `ets_element_builder.js` 改修）

- `00_テンプレート` カテゴリのボタン一覧に「一括生成モード」トグルを追加
- トグル ON の間は各テンプレボタンにチェックボックスを表示し、ボタンクリックは選択トグルとして動作する（通常のテンプレ適用は行わない）
- ヘッダーに「一括生成 (N件)」実行ボタン・「停止」ボタン・進捗表示（例: `3/8: テンプレ名`）を追加
- 結線（クラス間参照）は既存規約どおり `EasyTemplateSelector` の constructor で行う（`javascript/` 配下のトップレベルで他ファイルのクラスを参照しない）

### 3. 状態遷移とエラー処理

- 実行中はテンプレ適用系 UI を disabled にし、二重実行を防ぐ
- 1 件の失敗（適用タイムアウト・生成タイムアウト）は console にエラー（日本語）を出して次のテンプレへ進み、最後に成功/失敗件数を進捗表示へ出す
- ユーザーが生成中に手動 Interrupt した場合は「その件の完了」として次へ進む（Generate ボタン復帰の監視により自然にそうなる）

## データフロー

```
[開始時] ポジティブ欄 → SWAP_PREFIXES 抽出 → swapSections（実行中は固定）
[各テンプレ] fetch 済みテンプレ本文 → applyTemplate() → 安定待ち
           → プロンプト欄のセクション差し替え（updateInput で Gradio 同期）
           → Generate クリック → 完了待ち → 次へ
```

- 差し替えは `textarea.value` 直代入 + `updateInput()` で行う。キャレット同期は `event.isTrusted` 判定により誤発火しない（既存の仕組みに乗る）
- Undo 履歴には積まない。バッチ実行はテンプレ適用の連続であり、`applyTemplate` 側の `resetTextHistory()` に任せる

## 制約・非対象

- 実行中はブラウザタブを開いたままにする必要がある（JS 駆動のため）
- ネガティブ欄は差し替え対象外（キャラ/衣装セクションは通常ポジティブのみ）
- キャラ/衣装のプリセット保存・API バッチ実行・外部キュー拡張連携はスコープ外

## テスト方針

- セクション抽出・差し替えの純粋関数に `node --test` の単体テストを追加（対象セクションなし・複数箇所に分散・サブ分類カテゴリ・入れ子カッコ入りラベルのケースを含む）
- 待機・実行ループは WebUI 実機で確認: 2〜3 テンプレ選択、キャラあり/なし混在、モデル切替を跨ぐケース、途中停止
